# TraceMind V2.0-A 基线可信化 — 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans(inline,本任务由探索过全部上下文的主 Agent 执行)。

**Goal:** 在不改变 SCN-001/002 诊断、审批、执行、验证、Replay、SSE 行为的前提下,完成干净克隆门禁、可观测性契约冻结、UTC 时间语义统一、未知动作 fail closed、Run 上下文冻结与版本冻结前移、checkpoint 契约钉死,使基线可信。

**Architecture:** 全部为既有 ai-service/compose/scripts 的定点修复 + 一个新 migration(009);不引入新服务、不做 Capability 抽离(留给 V2.0-B)。

**Tech Stack:** Python 3.12 / FastAPI / SQLAlchemy 2 / LangGraph 1.2.10(SqliteSaver)/ MySQL 8 / Docker Compose。

## Global Constraints

- 不修改已发布 migration(002~008);新变化只进 `009_v20_run_baseline.sql`。
- 不提交真实密钥;`.env.vm`、`secrets/mcp_clients.json` 保持 gitignored,只提交 example。
- 不使用默认根因、默认动作、fake 兜底掩盖失败;fail closed。
- 保留 SCN-001/002 现有诊断/审批/执行/验证/Replay/SSE 行为;行为特征测试先钉住再改。
- 不对历史数据做批量 ±8h;时间来源统一到"应用生成 naive UTC"。
- 测试命令:`cd ai-service && .venv/Scripts/pytest.exe tests/ -q`(基线 436 passed)。

### Task 1: 行为特征测试(先钉住现有行为,必须全绿后才开始改生产代码)

SCN-001/002 全图 fixture 运行(复用 test_approvals.py 的 FakeMCP/monkeypatch 模式,InMemorySaver),断言:根因代码、proposal action、approval/execution/recovery/replay 字段、工具白名单集合、needs_human 路径(无进展 / 双确认冲突 / 决策预算耗尽 / 执行预算耗尽)。

### Task 2: 未知根因/未知动作 fail closed(先红后绿)

- build_proposal:未知/缺失 root_cause_code → `ValueError("unknown_root_cause:...")`,删回退。
- propose_fix:捕获 ValueError → status=needs_human, termination_reason="unknown_root_cause",写 FIX_PROPOSED failed 回放;human_approval 顶部加守卫(status != awaiting_approval 或无 approval → 直接 return,不再 interrupt)。
- execute_fix:action_type 不在 {"CREATE_INVENTORY_INDEX","TERMINATE_BLOCKING_SESSION"} → status=failed + error=unknown_action_type,零写操作。
- fix_service:删 `else "CREATE_INVENTORY_INDEX"` 默认。
- 测试:未知根因 → 无 FixProposal/Approval/Execution 落库、needs_human;未知 action → 写操作 0。

### Task 3: 审批 CAS + 准确 Run 绑定(先红后绿)

- `approval_repo.decide_approval_cas(approval_id, *, decision, approver, comment, now_utc) -> Approval | None`(原子 UPDATE ... WHERE status='pending' AND (expires_at IS NULL OR expires_at>:now_utc))。
- `approval_repo.create_approval` 增加 `agent_run_id` 参数;propose_fix 传 `state["run_id"]`。
- approvals.decide:CAS 失败→区分 409 already-decided/expired;恢复/回放绑定 approval.agent_run_id(仅 legacy NULL 回退 runs[0],加注释)。
- approval_scanner:同上绑定。
- migration 009 含 approval.agent_run_id(见 Task 6);models.py 同步。
- 测试:并发双批准仅一个成功;approval 绑定 run A 时 decision/scanner 只恢复 A(即使 incident 有更新 run B);过期 CAS 返回 None。

### Task 4: UTC 时间语义统一

- compose.yml mysql:`TZ: UTC` + `--default-time-zone=+00:00`;compose.yml/compose.ci.yml/application.yml JDBC `serverTimezone=UTC`。
- audit_repository.py 三处 NOW() → 应用侧 `utcnow()` 参数。
- migrate.py started_at/applied_at → Python UTC 参数。
- eval_run_repo.insert_eval_run 显式写 created_at=utcnow()。
- engine.py:get_control_engine/get_readonly_engine/get_executor_engine/get_terminator_engine/get_engine_from_url 统一 `connect_args={"init_command":"SET time_zone='+00:00'"}`(经共享 helper)。
- `scripts/audit_time_sources.py`:只读审计(session tz、NOW() vs UTC_TIMESTAMP、CURRENT_TIMESTAMP 默认列清单、关键表 max(created_at) 偏差)。
- 测试:audit_repository 写入值为应用 UTC(用 fake engine 捕获参数);引擎 init_command 存在;audit_time_sources 脚本可运行(不依赖业务库时跳过业务表)。

### Task 5: RunContextSnapshot 冻结 + 版本冻结前移

- versions.py 新增 `CAPABILITY_BUNDLE_VERSION="1.0"`、`PROMPT_BUNDLE_VERSION="1.0"`(注释:V2.0-B 起由 Capability/Prompt 目录接管版本生命周期)。
- 新建 `app/services/run_context.py`:Pydantic `RunContextSnapshot`(schema_version/incident_id/agent_run_id/service_ref(必填)/severity/affected_*/incident_title/investigation_window/baseline_ref/healthy_baseline_ref/checkpoint{thread_id,namespace}/bundle_versions/frozen_at)+ `build_snapshot(incident, run_id, thread_id, baseline)` + `load_snapshot(run) -> RunContextSnapshot`(缺失/不完整/校验失败 → RunContextMissing/Invalid 异常)。
- run_repo.create_run(incident_id, baseline, *, incident):同一事务 flush→构建快照→写 run_context_snapshot_json/checkpoint_thread_id(=thread_id)/checkpoint_namespace("")/expected_policy_bundle_version/capability/prompt/tool 版本;incident.service_ref 缺失 → ValueError(fail closed,不再默认 inventory-service)。
- runner.start_investigation:从快照构建 initial state(不再读 Incident 行);异常 → run failed + incident needs_human(termination_reason=context_snapshot_invalid)。
- runner.recover_pending_runs:同上;快照缺失 → fail closed(不猜、不用默认)。
- `_finalize_run` 保留终态 RUN_TERMINATED 回放;`freeze_run_versions` 保留(收尾只读确认,不再作为首次写入点)。
- 测试:创建 Run 后 incident 行被改(service_ref/operation_ref 更新),恢复后 initial state 仍为快照值;快照缺失 → needs_human 且不 invoke 图;run 与 thread 1:1。
