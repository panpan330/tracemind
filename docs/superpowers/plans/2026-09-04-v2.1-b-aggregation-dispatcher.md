# TraceMind V2.1-B "聚合与调度" 实施计划

> **For agentic workers:** 本切片按方案 §V2.1 条目 4-8 实施;V2.1-C(resolved 复核闭环、
> 历史健康基线采集、告警闭环 E2E)不在本轮。TDD:先写聚合/Dispatcher 特征测试(红),再实现。

**Goal:** 告警经 Webhook 快速持久化后,由聚合事务创建/聚合 Incident 并插入 queued Run;
数据库租约 Dispatcher 异步领取并启动调查;崩溃后租约回收、准确 Run 恢复。

**Architecture:** Webhook(同步、快速)= 事件/投影/聚合事务/queued Run 插入;
Dispatcher(后台 loop)= 租约领取 → 快照驱动的 start_investigation。单实例声明不变。

**Tech Stack:** 纯后端;无 LLM 变化;前端不动(新字段只增不改)。

## Global Constraints

- Webhook 不同步运行 Agent、不同步采集基线(方案 V2.1-4);
- `open_group_key` 活动期唯一(利用 NULL 可重复);`active_run_key` 活动 Run 唯一;
- Incident 状态三分离:`alert_status`(FIRING/RESOLVED,来自告警)/
  `lifecycle_status`(OPEN/CLOSED,C 阶段才关闭)/ `agent_run.status`(运行语义,含新增 queued);
- 每 Incident 默认只允许一次告警触发的自动 Run(终态后重复 firing 只累计 occurrence,不自动重跑);
- fail closed:labels 缺 service/operation 或不在 MCP 白名单 → 建 Incident 但不建 Run(转人工语义);
- 未推送的 V2.1-A 链已完成验收(595414e 已在 origin/main)。

## 二、数据迁移方案(migration 011_v21_aggregation.sql,追加式)

```sql
USE tracemind_control;
ALTER TABLE incident
  ADD COLUMN source VARCHAR(32) NOT NULL DEFAULT 'manual',
  ADD COLUMN alert_name VARCHAR(128) NULL,
  ADD COLUMN environment VARCHAR(32) NULL,
  ADD COLUMN alert_status VARCHAR(16) NULL,          -- FIRING/RESOLVED(manual 为 NULL)
  ADD COLUMN lifecycle_status VARCHAR(16) NULL,      -- OPEN/CLOSED(C 阶段关闭)
  ADD COLUMN group_key VARCHAR(190) NULL,            -- alertname:environment:service:operation
  ADD COLUMN open_group_key VARCHAR(190) NULL,       -- 活动期=group_key,关闭置空
  ADD COLUMN first_seen_at DATETIME(3) NULL,
  ADD COLUMN last_seen_at DATETIME(3) NULL,
  ADD COLUMN occurrence_count INT NOT NULL DEFAULT 1,
  ADD COLUMN labels_json JSON NULL,
  ADD COLUMN annotations_json JSON NULL,
  ADD UNIQUE KEY uk_incident_open_group (open_group_key),
  ADD KEY idx_incident_group (group_key);

ALTER TABLE alert_instance
  ADD COLUMN incident_id BIGINT NULL, ADD KEY idx_alert_inst_incident (incident_id);

CREATE TABLE IF NOT EXISTS incident_alert (
  id BIGINT AUTO_INCREMENT PRIMARY KEY,
  incident_id BIGINT NOT NULL,
  alert_instance_key VARCHAR(190) NOT NULL,
  UNIQUE KEY uk_incident_alert (incident_id, alert_instance_key),
  KEY idx_ia_alert (alert_instance_key)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

ALTER TABLE agent_run
  ADD COLUMN active_run_key VARCHAR(64) NULL,        -- 活动期=incident:{id}
  ADD COLUMN lease_owner VARCHAR(64) NULL,
  ADD COLUMN lease_until DATETIME(3) NULL,
  ADD COLUMN dispatch_attempts INT NOT NULL DEFAULT 0,
  ADD UNIQUE KEY uk_agent_run_active (active_run_key),
  ADD KEY idx_agent_run_dispatch (status, lease_until);
```

- 存量数据兼容:默认 'manual'/NULL,旧行不聚合;本地测试库按协议(备份 → 官方迁移器 → 验证)应用。
- 基线窗口列(baseline_window_*)属 V2.1-C 的 012,不在本版。

## 四、并发与重启测试计划(先红后绿)

1. 并发同 group FIRING×10(线程):最终 1 个 OPEN Incident + 1 个 queued Run +
   occurrence_count=10;open_group_key 冲突被捕获重读(无 500)。
2. 并发不同 group:各自建 Incident,互不聚合。
3. 并发同 Incident 建两个 Run(active_run_key 冲突):仅 1 个 queued 成功。
4. Dispatcher CAS 领取:queued → investigating;两个并发领取循环同抢 → 仅一个成功(rowcount)。
5. 租约回收:queued + lease_until 未来 + owner='dead' → 不领取;租约过期 → 领取成功。
6. Dispatcher 领取后崩溃模拟:status 仍 queued + 租约过期 → 下一轮重新领取并成功启动;
   已 investigating 的 Run 由 recover_pending_runs 恢复(现有),Dispatcher 不重复启动
   (status 过滤)。
7. 终态 Run 后重复 firing:occurrence+1、不新建 Run、active_run_key 已清空但不自动重跑。
8. labels 不完整:Incident OPEN + 无 queued Run(状态 needs_human?B 决策:incident.status
   = 'created' 不动,报告字段 visible;C/B 复核人工接管)。
9. 原有网关测试适配:FIRING 后 created_incidents 有值(断言更新,语义按 B)。
10. 迁移 011 内容门禁(唯一键/无密码)+ 本地真库备份后增量应用。

## 五、风险点

1. **聚合事务含 Run 创建**(create_run 内含 FOR UPDATE 读 incident):与 open_group_key
   唯一约束叠加后事务较长——量级仅 demo(QPS 低),锁窗口毫秒级;测试 1 覆盖。
2. **Dispatcher 与 approval_scanner/runner 的并发**:start_investigation 在 Dispatcher
   协程内跑图(to_thread),与 approval resume 并发时同 run 级别安全(V2.0-A 已有
   快照/锁);新增 queued 只会由 Dispatcher 恢复,run 状态机有 CAS。
3. **E3 语义取舍**:queued Run 的 digest baseline 为 None → E3 增量=累计值,
   诊断可判但口径偏松;V2.1-C 历史基线窗口替换(写入报告与交接文档,不算回归)。
4. **手工 Run 与自动 Run 的 active_run_key 互斥**:手动启动时若自动 Run 活动中 →
   409(报告明确;前端未接,无破坏)。
5. **model_router 偶发**:已修(routing_epsilon=0),不在本版范围。
6. **多实例**:仍声明单实例;Dispatcher 租约设计为未来多实例预留但未验证跨机。
