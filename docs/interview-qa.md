# 面试 Q&A(TraceMind 项目)

> 基于 V1.1-V1.14 的落地经验,每个答案 3-5 句,紧扣本项目。

## 1. 这个项目解决了什么问题?

传统故障诊断依赖人工看监控、慢查询、执行计划,耗时且易漏。本项目用 LangGraph 编排 AI Agent 自动完成"假设 → 取证 → 根因 → 修复 → 验证 → 复盘"闭环,证据全部来自真实系统(MySQL 执行计划 / 慢查询 / 锁等待 / P95 指标),诊断过程可审计、可回放、可量化。

## 2. Agent 怎么防幻觉?

两条防线:一是**证据闸门**(E1~E5 / L1~L6 事实检查),LLM 只能提出假设,根因结论必须由真实证据确认,未满足证据闸门就继续取证而不是猜;二是所有数据来自真实系统而非 LLM 编造,工具调用与决策全量审计。

## 3. 多 Agent 怎么设计?

本项目是"单 Agent 能力纵深"演进:长期记忆(历史案例复用)→ 反思(失败自我改进)→ 多模型路由(按任务难度选模型)→ 动态路由学习(数据驱动选优)。多 Agent 协作是把这些能力按角色拆分(Planner 拆任务 / Worker 并行取证 / Reviewer 交叉审查),每层有独立数据与降级路径。

## 4. 怎么验证 Agent 改进有效?

量化评测平台:每次改进跑 SCN-001 / SCN-002 多轮,记录成功率 / 耗时 / 成本,可视化趋势。后端 422 个测试 + 前端 45 个测试 + 真实模型验收——"改进有效"是数据证明,不是拍脑袋。

## 5. RAG 检索不到怎么办?

降级不阻塞:检索失败记录 rag_degraded 事件,Agent 用确定性数据源继续诊断;记忆侧把失败案例沉淀为负样本(避坑参考),下次相似问题不重复失败路径。检索 / 沉淀 / 反思任一失败都不中断主流程。

## 6. 模型成本怎么控?

节点级路由:强推理节点(hypothesize / reflect)用 qwen3.8-max,高频工具节点(select_tool / report)用 qwen3.7-flash;动态路由学习按窗口评分(成功率 0.6 / 时延 0.25 / 成本 0.15)自动选优。实测单次诊断成本 ¥0.0153。

## 7. human-in-the-loop 怎么设计?

审批作为状态机节点:唯一写路径 + 前置校验 + 过期自动拒绝;锁场景处置(KILL)执行前复核目标未变 / 仍持锁 / 账号白名单,负例零误杀。修复失败走反思重试,重试用尽才转人工。

## 8. 工具层为什么用 MCP?

MCP 标准化工具协议:工具实现唯一(stdio / HTTP 只是 transport 适配器,零 direct 旁路),权限隔离(五账号 / 三连接池 / 白名单参数),每次调用两段式审计 + 回放。升级到 Streamable HTTP 后独立容器、可水平扩展。

## 9. 长上下文怎么处理?

EvidenceSummarizer 上下文压缩:证据超阈值(8 条)自动摘要,控制 LLM 输入 token;配合长期记忆只注入 top-k 相关案例(前 300 字符),避免无界上下文与 token 爆炸。

## 10. 测试怎么做的?

TDD:先写失败测试再实现;repo / API 测试用 FakeEngine / TestClient 不连真实库;真实模型验收在 VM 跑 SCN 闭环(观测栈 + qdrant 环境自查),遇额度错误立即停止并告知。全量回归:后端 422 测试 + 前端 45 测试。
