# 面试演示脚本(5 分钟版)

> 前置:服务已就绪(Docker 方式:`docker compose up -d` 后全部 healthy;本地方式见 README)。
> 建议提前在浏览器打开 `http://localhost:8080`,并准备好终端跑 `verify-m5.py` 作为命令行闭环佐证。

## 第 0 屏:架构一句话

> "这是一个 AI 故障诊断平台:微服务出问题时,Agent 不靠猜,而是像工程师一样基于真实证据(慢 SQL、执行计划、P95)定位根因,并且任何写操作都必须人工审批。"

## 第 1 屏:场景与事件列表(约 1 分钟)

- 点「重置环境」:强调"索引重建,健康基线已恢复"。
- 点「注入故障」:inventory 的联合索引被删除(演示故障可逆注入)。
- 创建 Incident(级别/服务/描述),点「开始调查」。

## 第 2 屏:调查详情 + SSE 实时(约 2 分钟)

- 观察状态实时流转:`investigating → awaiting_approval`,SSE 推送的假设卡片、证据链逐条出现。
- 讲 E1~E5 闸门:逐条展开证据表——
  - E1 P95 从 2ms 涨到 ~120ms;
  - E4 执行计划从 `ref/1 行` 变成 `ALL/50万行`;
  - E5 索引元数据确认缺失。
- 强调:**五条证据齐备才判定根因**,证据不足会继续调查或转人工(不猜)。

## 第 3 屏:审批面板(约 1 分钟)

- 展示修复方案:动作 CREATE_INVENTORY_INDEX、风险 medium、参数哈希。
- 点「批准」→ 状态立即变为 `executing → recovered`。
- 顺带讲:唯一写路径 + 六项校验 + 过期自动拒绝;Agent 永远没有任意 SQL/Shell 权限。

## 第 4 屏:复盘报告(约 1 分钟)

- 展示根因、证据链、修复执行、恢复验证(P95 回到基线)。
- 结尾金句:"整个调查过程每一步工具调用、每个决策都落库,可以回放审计——这是 Agent 系统落地最关键的信任问题。"

## 命令行佐证(可选,约 15 秒)

```bash
python scripts/verify-m5.py --base http://localhost:8000
# 输出:注入 → 调查 → 审批 → 恢复 → 报告,全链路 PASS
```

## 面试追问准备

| 可能的问题 | 回答要点 |
|---|---|
| LLM 幻觉怎么办? | 根因是 E1~E5 规则闸门确认的,LLM 只做假设生成与报告润色;工具结果经 Pydantic 校验,缺失数据返回错误而非编造 |
| 为什么用 LangGraph 不用简单脚本? | 需要中断-恢复(人工审批)、条件分支(证据不足回退)、持久化检查点(重启恢复),状态机是天然建模 |
| 审批超时/服务重启? | 30s 过期扫描自动转 rejected 并恢复图;检查点持久化,重启后恢复未完成任务 |
| 生产级差距? | 认证/授权、多租户、真实 LLM(接口已留,V1.1 接 OpenAI-compatible)、指标真实采集扩到更多场景 |
| 怎么证明不是玩具? | 真实 MySQL 数据与执行计划、50 万行、可重复注入/恢复、49+ 后端测试 + E2E 验收脚本 |
